# 小哲用工风险检测系统（网页版）

> 面向中小企业的**用工风险检测工具**：录入或导入用工数据（员工、合同、考勤、薪资、社保、证照）→ 系统自动测算每个人身上的用工风险 → 算不出的走合规自查 → 每条风险附法条与整改步骤 → AI 用人话解读。

- **在线体验**：https://yongong-guanjia-production.up.railway.app
- **代码仓库**：https://github.com/nxwangjun/yongong-guanjia-web
- 许可：MIT　|　AI 能力：真实大模型（RAG 检索增强，模型 `deepseek-v3`）

## 一、解决什么问题

中小企业普遍没有专职法务，用工违规（未签合同、试用期超限、加班超时、低于最低工资、未缴社保、证照过期）往往在劳动监察或仲裁发生时才被发现，此时已是罚款与赔偿。

本系统把这套排查做成随时可用的工具：

| 环节 | 以前 | 现在 |
|---|---|---|
| 发现问题 | 等员工投诉或监察上门 | 录入数据后自动测算，主动暴露 |
| 定位问题 | 只知道"好像有问题" | 下钻到"张三入职 448 天无合同" |
| 整改 | 不知道改什么 | 每条风险附法条 + 后果 + 分步骤整改 |
| 请教律师 | 小事也要付费咨询 | 先问 AI（附法条依据），必要时再找律师 |

## 二、快速开始

**零第三方依赖，无需 npm install。**

```bash
node server.js          # 启动（默认 http://localhost:3000）
```

打开浏览器访问 `http://localhost:3000` 即可。首次启动自动生成 12 人演示数据（预埋 9 类常见风险，可直接看到检测效果）。

其他命令：

```bash
npm test                # 端到端冒烟测试
npm run corpus          # 重建劳动法检索语料（需本地既有知识库）
npm run rules           # 重建 116 条规则库（需本地既有知识库）
```

> 要求 Node ≥ 18（用到内置 `fetch`）。知识语料已随仓库提交，clone 下来即可运行。

### 内置演示账号

系统只有两个角色：**管理员**（全部权限）与**普通用户**（录数据、看检测、用 AI，不能进系统设置与成员管理）。

| 角色 | 账号 | 密码 | 权限 |
|---|---|---|---|
| 管理员 | `admin` | `admin123` | 全部模块 |
| 普通用户 | `user` | `user123` | 除「成员账户 / 系统设置」外全部 |

管理员可在「系统 → 成员账户」生成邀请码，同事拿码在登录页选「邀请码加入」即成为普通用户。也可在登录页「注册建公司」开新公司（数据完全隔离）。

## 三、功能清单

### 检测（核心价值）
| 模块 | 说明 |
|---|---|
| **检测概览** | 员工总数 / 存在风险的员工 / 高危问题 / 风险项合计，一屏看全貌 |
| **员工风险画像** | 逐人列出命中了哪些风险、为什么、依据哪条法、怎么整改 |

### 风险
| 模块 | 说明 |
|---|---|
| **风险清单** | 一键扫描；按严重程度排序；**下钻到具体哪个人、为什么**；附法条原文；AI 逐条解读 |
| **合规自查** | 系统算不出的 105 条，逐条确认（已做到 / 没做到 / 待核实） |
| **风险处置** | 派发 → 整改中 → 关闭，闭环可追踪 |
| **规则配置** | 116 条规则启停 |
| **AI 问答** | 自由提问劳动法问题，基于知识库检索作答并附依据 |

### 数据
| 模块 | 说明 |
|---|---|
| 员工档案 | 花名册、在职状态、入离职、工号 |
| 合同信息 | 签订、续签、到期；试用期上限按合同期限自动核算 |
| 考勤工时 | 出勤与加班记录，月加班超 36 小时触发风险 |
| 薪资 | 月工资、加班费；低于最低工资 / 试用期工资不足转正 80% 触发风险 |
| 社保 | 参保状态与基数，在职无参保、基数低于工资触发风险 |
| 证件资质 | 特种作业证等有效期管理，到期前提醒 |
| 数据导入 | Excel / CSV / JSON 导入导出（表头中文，改完可直接导回） |

### 系统
| 模块 | 说明 |
|---|---|
| 成员账户 | 成员列表、停用/启用、邀请码 |
| 系统设置 | 企业信息、所在地区（自动带出当地最低工资）、判定阈值、**大模型密钥配置** |

## 四、技术实现

### 整体架构

```
浏览器（原生 JS SPA）
      │
      ▼
Node 内置 http 服务（server.js，零第三方依赖）
      ├── 业务 API（CRUD / 扫描 / 处置 / 导入导出）
      ├── 扫描引擎（engine.js：116 条规则判定）
      ├── 检索器（retriever.js：BM25，469 条劳动法语料）
      └── AI 智能体（agent.js）
              ├── 真实大模型调用（OpenAI 兼容协议）
              └── 未配置密钥时 → 本地规则引擎兜底（明确标注，不伪装 AI）
```

### 关键技术点

**1. 检索增强（RAG）**
自建 BM25 检索器，中文按「单字 + 二元组」切分（无需分词库），在 469 条语料（249 条法条正文 + 116 条规则 + 104 条风险点）上召回依据，作为大模型作答的**唯一事实来源**。所有 AI 回答必须基于检索到的法条，超出知识库时明确说明"未覆盖，建议咨询律师"，从机制上抑制幻觉。

**2. 真实大模型接入**
标准 OpenAI 兼容协议 `/chat/completions`，默认 DeepSeek，可换任意兼容端点（OpenAI / 通义 / 智谱 / 比赛方接口等）。密钥走 `.env`，也支持在页面「系统设置」里粘贴、立即生效。

**3. 双引擎降级（不伪造 AI）**
未配置密钥或调用失败时，自动切换本地规则引擎——仍基于同一份语料检索并结构化合成，但**在返回结果中标注 `mode:'local'` 并明确提示"非 AI"**。绝不把规则输出伪装成 AI 生成。

**4. 规则判定（原创实现）**
16 条规则由系统数据直接算出、下钻到人（未签合同、满一年未签视为无固定期限、合同到期未续签、试用期超限、二次固定期限、月加班超 36 小时、低于最低工资、试用期工资不足 80%、试用期工资低于最低工资、加班未付加班费、加班费低于法定标准、未缴社保、社保基数低于工资、离职无证明、证照到期等）；其余走合规自查。判定逻辑在本项目中重新实现。

**5. 法条来源**
法条正文取自元典核验的现行有效版本，逐条记录发布/实施日期与文号。

## 五、AI 配置

复制 `.env.example` 为 `.env`，填入：

```ini
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-你的密钥
LLM_MODEL=deepseek-chat
```

或在页面「系统设置 → 大模型配置」里直接粘贴，立即生效（会写入 `.env`）。

未配置时系统仍可完整运行（本地规则引擎兜底），AI 回答会明确标注"本地规则引擎，非 AI"。

```
│   └── js/  api.js · ui.js · app.js · pages/{login,hr,risk,system,people}.js

```
