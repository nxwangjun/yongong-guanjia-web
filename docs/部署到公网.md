# 公网部署：一步一步照着做

> 目标：拿到一个公网网址，评委在任何地方打开就能用。
> 全程不用写代码、不用命令行（除非你选了"让我帮你推"那条路）。

---

## 先搞清楚：要什么账号？

| 账号 | 干什么用 | 要不要钱 | 怎么办 |
|---|---|---|---|
| **GitHub** | 放代码的地方（相当于网盘） | 免费 | github.com → Sign up → 邮箱注册 |
| **Railway** 或 **Render** | 真正跑服务、给网址的那家 | 免费额度够用 | 直接用 GitHub 账号登录，**不用再注册、不用绑信用卡** |

**两个就够，都免费。**

---

## 方案 A：Railway（推荐，不休眠）

> 推荐理由：免费额度内**不会休眠**，评委随时点开都是秒开。Render 免费层 15 分钟没人访问就会睡，第一次点要等 30-50 秒，评委体验会打折扣。

### 第 1 步：把代码放到 GitHub

1. 打开 github.com，右上角 **+** → **New repository**
2. Repository name 填：`yongong-guanjia-web`
3. 选 **Public**（公开 —— 比赛"开源许可"是加分项，而且公开仓库部署更省事）
4. **不要**勾选 Add a README（我们本地已经有了）
5. 点 **Create repository**
6. 在接下来这个页面，点 **uploading an existing file**（上传已有文件）
7. 打开你电脑上的项目文件夹 `C:\Users\Administrator\WorkBuddy\Claw\yongong-guanjia-web`，把里面**所有文件和文件夹**拖进浏览器窗口
   - 注意：不要把 `node_modules` 和 `.env` 拖进去（`.env` 里有密钥，平台其实会自动忽略，但别传最保险）
8. 拖完点 **Commit changes**

> 文件路径很深，找不到文件夹？在文件管理器地址栏直接粘 `C:\Users\Administrator\WorkBuddy\Claw\yongong-guanjia-web` 回车。

### 第 2 步：Railway 部署

1. 打开 railway.app → **Login** → 用 GitHub 账号登录（会让你点一次 Authorize）
2. 登录后点 **New Project** → **Deploy from GitHub repo**
3. 选刚才建的 `yongong-guanjia-web`
4. Railway 会自动识别根目录的 `railway.json`，**什么都不用填**，等它跑完（1-2 分钟）
5. 部署完点进服务 → **Variables**（变量）→ **+ New Variable**，加三个：
   - `LLM_API_KEY` = 把比赛平台给你的那串 key 粘进来（`sk-` 开头）。**只填在平台面板里，不要写进任何文件。**
   - `LLM_BASE_URL` = `https://api.openai-next.com/v1`
   - `LLM_MODEL` = `deepseek-v3`
6. 回到 **Settings** → **Networking** → 点 **Generate Domain**（生成域名）
7. 拿到形如 `https://yongong-guanjia-web-production.up.railway.app` 的网址

### 第 3 步：验证

浏览器打开 `https://你的网址/api/health`，看到里面有 `"llmEnabled": true` 就成功了。
再打开根网址，右上角状态灯应该是**绿色「AI 已接入」**。

## 方案 B：Render（Railway 搞不定就用这个）

> 缺点：免费层 15 分钟无人访问会休眠，首次打开要等 30-50 秒。
> 补救：注册 uptimerobot.com（免费），加一个监控每 10 分钟访问一次你的网址，就不会睡。

步骤几乎一样：

1. 代码同样先传到 GitHub（见方案 A 第 1 步）
2. 打开 render.com → **Get Started** → 用 GitHub 登录
3. **New** → **Web Service** → 选你的仓库
4. 填这几项（其余默认）：
   - Name：`yongong-guanjia`
   - Runtime：`Node`
   - Build Command：**留空**
   - Start Command：`node server.js`
5. 往下翻到 **Environment Variables**，加那三个变量（同上）
6. 点 **Create Web Service**，等几分钟
7. 拿到 `https://yongong-guanjia.onrender.com`

## 方案 C：应急（拿不到网址时的兜底）

如果上面都卡住，用**内网穿透**把你本机端口变成公网地址：

1. 下载 cpolar（cpolar.com）或 natapp，注册免费账号
2. 装好后一条命令：`cpolar http 3000`
3. 它会给你一个临时公网网址

**缺点：你电脑必须开着、服务必须跑着**，关机或断网链接就失效。只适合录演示视频和临时给别人看，不建议写进参赛材料。

## 部署后要检查的三件事

- [ ] 打开 `/api/health`，确认 `"llmEnabled": true`
- [ ] 打开首页，右上角是**绿色**「AI 已接入」
- [ ] 点「风险清单」能扫出 11 条，点「AI 解读」10 秒内能出结果

## 常见坑

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 打不开 / 502 | 还在部署或构建失败 | 去平台看 Deploy Logs，多半是 Node 版本问题，加变量 `NODE_VERSION=20` |
| 状态灯是橙色「本地规则引擎」 | 密钥没生效 | 检查环境变量 `LLM_API_KEY` 有没有填对、有没有重启服务 |
| 页面能开但数据空 | 首次会自动生成演示数据 | 刷新一下；或去「系统设置」恢复演示数据 |
| 用几天后打不开 | 免费额度用完或休眠 | Railway 看额度；Render 用 UptimeRobot 保活 |

## 安全提醒

- 密钥**只**放在平台的环境变量里，不要写进任何文件，`。env` 已经在 `.gitignore` 里不会上传。
- 比赛方这个 key 有效期到 **2026-10-04 23:30**，过期后页面会自动降级为本地规则引擎（仍能用，只是 AI 那部分失效）。路演前记得确认没过期。
